# Scoring rubric

Score honestly. Inflated scores make the whole review worthless. Most real
codebases at this stage land 4-6 in most categories, and that is not an insult.

## Severity bands

Every finding carries one. These are the definitions the report and the caps below both use.

| | Band | Meaning |
|---|---|---|
| 🔴 | CRITICAL | Loses money, renders a wrong price as if it were right, exposes a credential, corrupts data, produces a signal from lookahead, or crashes on a normal market event. |
| 🟠 | HIGH | Wrong under a common condition (token expiry, disconnect, holiday, halt, missing candle), or a security gap one step from exposure. |
| 🟡 | MEDIUM | A real bug or real debt with a bounded blast radius. |
| 🔵 | LOW | Hygiene, naming, minor duplication, a missing test on a low-risk path. |

## The 0–10 scale

| Score | Meaning |
|---:|---|
| 0–1 | Absent, or actively dangerous. Wrong prices, leaked credentials, fabricated data. |
| 2–3 | Exists, works on the happy path only. No error handling, no tests, obvious correctness holes. |
| 4–5 | Reasonable structure, but at least one failure mode will bite in normal use. Sparse tests. |
| 6–7 | Solid. Handles the common failure modes deliberately. Tested. Some gaps under load or at edges. |
| 8 | Well built. Failure modes handled AND detectable. Meaningful tests. A specialist would find only refinements. |
| 9 | Would survive a hostile production review with minor notes. Rare. |
| 10 | Nothing to add. Effectively never awarded — if you're about to give a 10, look harder. |

## Anchors that override the vibe

Apply these before settling on a number:

- Any 🔴 finding in a category caps it at **3**.
- Any unmitigated 🟠 finding caps it at **5**.
- No tests in a category where tests are possible caps it at **4**.
- A failure that is **silent** (wrong data shown as if correct) caps the relevant
  category — Data Integrity, Indicators, or Signals — at **2**. Silence is worse than
  a crash; a crash tells you.
- A stated `CLAUDE.md` invariant violated caps that category at **2**.
- "It works when everything is up" is a 3, not a 6, no matter how clean the code is.
- Clean code with wrong math scores **low**. Ugly code with right math and real tests
  scores higher. Correctness dominates aesthetics in this domain.
- Untested indicator math is capped at **4** even if it looks right — you cannot
  award points for correctness you have not verified.
- Tests whose fixtures were generated by the implementation under test count as
  **zero tests** for scoring purposes. Say this out loud in the report.

## Overall score

Not a plain mean. Weight for this project:

| Category | Weight |
|---|---:|
| Data Integrity | 2.0 |
| Technical Indicators | 2.0 |
| Trading Signals | 2.0 |
| FYERS Integration | 1.5 |
| Security | 1.5 |
| Backend | 1.0 |
| Architecture | 1.0 |
| Production Readiness | 1.0 |
| Performance | 0.75 |
| Frontend | 0.75 |

Then apply one hard rule: **the overall score cannot exceed the lowest of Data
Integrity, Technical Indicators, and Trading Signals, plus 1.** An app that shows
wrong numbers beautifully is not a 7.

State the weighted arithmetic in one line so the number is auditable.

## Per-category output

For each category give: the score, one sentence on what earned it, and one sentence
naming the single change that would raise it most. No more than that — the detail
belongs in the findings.
